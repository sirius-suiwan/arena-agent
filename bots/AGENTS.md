# Bot 开发

写或改 bot 前先看 [接入和复盘指南](README.md)、[统一 Bot 协议](../protocol/bot/README.md) 和目标游戏的 `games/<game-id>/RULES.md`。同时遵守[仓库根目录规范](../AGENTS.md)。

## 参赛 Agent 的工作区

- 从最新的 `origin/main` 创建自己的独立分支和 worktree。在自己的分支上可以做小步本地提交；不要把个人 bot 合并或 cherry-pick 到 `main`，也不要直接在 `main` 开发个人 bot。没有明确授权，不推送、不发布或分享个人 bot 的源码、构建产物或提交。
- 工作区中的参赛 bot 只保留内置的 Laika、GPT-dots 和自己的 bot；保留公共文档。不要访问或运行其他参赛者的私有实现，也不要改动其他人的 worktree。可以在对局外单独分析获授权的录像，这不授权查看或运行对手代码。
- worktree 用于组织代码和减少误操作，不是安全边界。它和本地 bot 子进程都不能隔离同一操作系统用户能访问的文件；只运行可信代码。

## 接入和决策

- 算法和实现语言不限。自动注册目前只接受包内的 `.js`、`.mjs` 或 `.py` 入口；其他语言可用薄适配器接入，并在自己的 bot 目录写清构建、依赖和启动方式。不要为了某个 bot 修改公共宿主。
- 进程以 UTF-8 JSON Lines 通信，stdout 只写协议消息，stderr 写诊断。按[协议](../protocol/bot/README.md)在规定时间内，对每个收到的 `observe` 用原样 tick 回复一条合法动作；不要依赖超时补交。
- 实时决策只用本席收到的观测和自己的状态。不读取其他席位的指令、私有信息、裁判隐藏状态或本局实时日志。内置 Laika 的特权由宿主授予，不应通过名字、声明或旁路自行获取。

## 公平复测

- 每次只改一个策略假设。固定并保持引擎和基准 bot 的版本不变，用相同的规则版本、配置和一组固定种子比较改动前后结果，交换席位复测。不要为对比修改基准 bot 或公共裁判。
- 记下候选 bot 和基准 bot 的版本或哈希、规则版本、配置、种子和席位；单独记下 Laika 是否带宿主授予的刷箱预报、随机缩圈终点预报等能力，以及启用的席位。不要把带特权与不带特权的结果当作同一个基准。
