# Arena Agent

本地多游戏竞技场：编程 bot 和人类共用动作接口。首款游戏是按 4399 旧版重建的坦克迷宫对战。无需远程联机或向模型服务发请求。

## 工程结构

| 目录 | 责任 |
| --- | --- |
| `core/` | 通用裁判：固定 tick、选手和动作截止 |
| `protocol/` | bot、游戏及界面各自的接入契约 |
| `runners/`、`bots/` | 进程管理和选手示例 |
| `games/` | 每款游戏独立维护规则、验证、物理与画法 |
| `replay/`、`runs/` | 录制和验证代码；生成的数据不入库 |
| `viewer/`、`apps/cli/` | 浏览器界面与本地命令入口 |
| `tests/` | 单元、协议、可重放和接入测试 |

开发规范见 [AGENTS.md](AGENTS.md)。项目使用 Node.js 22+；Python bot 需要 Python 3。

## 快速开始

```sh
npm test
node apps/cli/arena.js run --seed 42 --bot-a laika --bot-b gpt-dots
node apps/cli/arena.js serve
```

CLI 输出本局目录。打开 [游戏选择页](http://127.0.0.1:8765/) 进入《坦克动荡 2》，或直接打开 [坦克菜单](http://127.0.0.1:8765/tank)。保留原有快捷模式；展开「自定义对局」可在 A–H 之间任选 2–8 个席位。每席可用已注册 bot、真人或留空。三套真人控制各限一席：方向键／M 或空格，ESDF／Q，以及鼠标；可分配到任意席位。实时和回放共享同一套绘图。网页只监听本机，不提供网络联机。选择「打开回放」并载入 `match.jsonl.gz`，即可播放、逐 tick 前后步进或点事件跳转。

```sh
node apps/cli/arena.js verify runs/tank-trouble/MATCH_ID/match.jsonl.gz
node apps/cli/arena.js report runs/tank-trouble/MATCH_ID/match.jsonl.gz > report.json
node apps/cli/arena.js report runs/tank-trouble/MATCH_ID/match.jsonl.gz --tick 123 > report-123.json
node apps/cli/arena.js run --seed 42 --rounds 10
```

网页会在当前浏览器、当前地址下自动保存对局选项、机器人与真人席位、队伍和坦克名称。刷新或重启服务后可继续使用；点「恢复默认」可清除这台浏览器保存的设置。种子不保存。

「对局详情」里的下场种子留空时每场随机；本场实际种子显示在地图旁，也写入对局清单。在相同设置和参赛席位下，手填同一个种子（包括 `0`）可复现地图和开局。CLI 不传 `--seed` 时每场随机；显式指定时，批量对局按该种子起逐场加一。

实时对局中的「停止对局」会完成当前 tick、结束比赛并保存已打的记录，不判胜负，也不能续打。「停止回放」会停止播放并回到第一帧，不改变日志。「对局详情」默认折叠，可展开计时、事件、动作与回放时间轴。

网页菜单「回放存储」可填写运行 Arena 的电脑上的绝对路径（也支持 `~/`）。保存后对同一份工程持续生效，重启服务或换浏览器也有效；只影响从网页新开的对局，不搬动旧录像。「使用启动默认目录」恢复 `serve --out` 或默认的 `runs/`。CLI `run --out` 不受网页设置影响。

实际对局存于「保存目录」下的 `<game-id>/<match-id>/`，对局 ID 可在实战和回放右上角复制。日志不主动附带 bot 源码或绝对路径，只记录入口文件名、注册 ID、哈希等可复盘信息及 bot 提交的动作。目录分离方便管理和分享，但不会隔离有同一本机文件权限的程序，也不会阻止根据动作推断策略。

- `manifest.json` 记录规则版本、种子、选手和运行参数；`result.json` 记录最终结果。
- `match.jsonl.gz` 是 gzip 压缩的 JSON Lines。每 tick 只存提交及采纳的动作、回退原因、事件和状态 SHA-256；不重复存地图、帧状态或各席观测。浏览器在本机解压并用当前规则生成画面，不上传文件、不运行 bot。CLI `verify` 逐 tick 核对哈希及事件，首处分歧会报出 tick。旧格式不迁移、不兼容。
- `report` 在验证后输出精简 JSON，包含版本、比分、回退、墙碰、命中和道具等统计与关键事件。分享给 Agent 时通常只需报告，不用给整局录像。加 `--tick` 可附上指定动作 tick 前后约两秒的上下文；原始日志可用 `gzip -dc` 查看。

## 接入 bot 或游戏

- [Bot JSONL 协议](protocol/bot/README.md)：每局一个常驻进程。支持受信任的本地 `.py`、`.js` 或 `.mjs` 脚本。内置 GPT-dots 和 Laika，可通过 `--bot-a` 和 `--bot-b` 替换。**本地进程不是安全沙箱。**
- [Bot JSON 注册](bots/README.md#注册到对战菜单)：放入脚本和 `bots/<目录>/bot.json` 即可在菜单选座或在 CLI 用注册 ID 对战。内置 Laika（复刻）和 GPT-dots 也用这套注册方式。
- [游戏适配器契约](protocol/game/README.md)：游戏决定 tick 频率及动作语义，宿主不解释物理。现有 [坦克规则](games/tank-trouble/RULES.md)；测试包含不同动作结构、不同 tick 频率的小型第二游戏。
- [本机界面协议](protocol/viewer/README.md)：画面与输入只是裁判的客户端。未来的《疯狂小人战斗》尚未接入。

写 bot 的 Agent 请从 [bots/README.md](bots/README.md) 开始，再看每款游戏目录的规则文件。坦克使用原版参数档，支持 2–8 席。默认 25 tick/秒，也可选 30 或 60；三档共享按秒计算的规则。主线只支持当前规则的录像，历史实现保留在 Git。

内置 Laika 带有独占刷箱预报，知道下次尝试的时间，并可在刷新前两秒拿到候选落点。无战斗或避险需要、未装备武器且候选点附近可通行时，它会提前靠过去，并留出刷箱所需的距离。候选可能变化，不改变裁判实际的刷箱和随机数。所有席位并发提交动作，不向 Laika 提供其他席位的动作，也不划拨时间。Laika 连续贴墙时仍会尝试短暂倒车或转向。启用情报的席位会标在地图旁，并记入清单与复盘报告。

「对局设置」可选择先到 3 分或打满 1–20 局，以及自动或手动选择开阔／经典／密集迷宫。地图大小默认根据实际参赛的真人和机器人总数调整，关闭的席位不计：2／3／4／5／6／7／8 席对应 12×9／12×10／13×10／14×10／14×11／15×11／16×12 格。切换到手动可固定宽高；CLI 也可用 `--cols`、`--rows` 指定。组队在「自定义对局」里分配 A–D 队，至少两队；友伤默认关闭，自伤仍有效。自由对战不在坦克旁标席位，组队时只标队伍字母。CLI 例：

```sh
node apps/cli/arena.js run --bot-a laika --bot-b gpt-dots --bot-c laika --bot-d gpt-dots \
  --simulation-rate 60 --round-limit 5 --cols 12 --rows 9 --maze-complexity dense \
  --teams '{"A":"1","B":"2","C":"1","D":"2"}' --friendly-fire off
```

`--round-limit` 是每场打几局；`--rounds` 仍是批量跑多少场。

每小局默认第 40 秒开始缩圈，用 15 秒缩完。安全范围保持地图的长宽比；坦克连续在外 2 秒才淘汰。只剩一辆坦克时，幸存者在结算阶段无敌。赛前界面可分别改开始时间和耗时，批量跑局也可用 `--shrink-after 40 --shrink-duration 15`（开始时间 0–120 秒，0 表示立即；耗时 1–120 秒）。都按游戏 tick 计时，不受浏览器帧率影响。

开局前可在「对局详情」给当前席位指定显示名，留空默认用注册名、bot 握手名字或席位 ID。实战和回放按选手统一坦克与其弹体配色；回放会自动用小圆圈跟随最终造成击毁的弹体；普通弹体不标记，实时对局不提示。展开「对局详情」仍可点「击杀标记」跳到命中帧。

实战和回放左侧显示当前局数与赛制，右侧是累计击杀（自伤不加），底部是各席位的名字、比分、普通弹空槽和特殊装备。超过四个席位时比分卡换行。新版保留每辆坦克 10 个普通弹槽；回放显示记录中的上限。普通弹命中或消失时释放一格，开火仍受按键状态和武器规则限制。

地图尺寸、复杂度默认按实占席位联动，也可分别手动选。人越多，刷箱越快、场上箱子上限越高。调试数值见 [classic-profile.json](games/tank-trouble/classic-profile.json)。改完重启并开新局。回放、校验及复盘依赖录像生成时的引擎与数值配置；修改数值后要复盘之前的对局，请从 Git 取回对应版本的文件。
